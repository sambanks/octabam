# The demand loader

25-28 Oct 2026. ✅ measured (port, `dsp_host`, or unit where stated), 🟡 inferred, ⬜ not looked at.
Addresses are `P:` / `X:` / `Y:` DSP words, or ColdFire virtual addresses where they start `0x4`.
Run on a unit: the ColdFire pump, the host write, the copier, the stub, the reverb guard's homes (sections "Measured on a unit", "Homes on a unit").
Port and `dsp_host` only: the hooked, soft SIDECHAIN_COMPRESSOR path.

## What it does

Every stock effect stays and works as stock. Window effects (SPECTRUM, CHARACTER, MODULATION, TRANSIENT, SHATTER; each remix's README lists its own) are in the
effect list and are copied into the DSP's shared window while a track uses them, and withdrawn when no track does.
SIDECHAIN_COMPRESSOR, which is stock COMPRESSOR with a side-chain on page 2, is loaded the same way while a track uses COMPRESSOR; it is reached
by hooks, not by its own id, and is "soft" (section "SIDECHAIN_COMPRESSOR"). Nothing of stock is removed, replaced or shrunk.
The window is stock's buffer memory, so the code goes only where no running stock effect writes.

`remixes/octabam` is built this way (`octabam-verbs`, `octabam-bus` and the `test/` remixes share its window layout).
`remixes/test/dlspike` is the same with one effect, for the gates.

## Design

Core B loads for both cores. The window is one memory, so code copied by B's hook is resident for A's tracks, and the pump
never writes to core A.

**Homes and collisions.** A demand effect has one or more homes (`Remix.window_homes` beside its address in `Remix.window`):
the blocks of the window it fits in, the code assembled once per home. At most one demand effect holds a block. A stock reverb
reaches an effect's code in a home when the code starts at or below the highest word the reverb writes (`stock.SLOT_EXTENT`:
PLATE `0x37ff`, SPRING `0xfff`, DARK `0x3da2`, counted from the block's base); each home's record carries that mask, bit i for
`REVERBS[i]`. In octabam every effect's code sits at the top of its block (offset `0x3820`; TRANSIENT's at `0x3e00` in the third and
fourth), so only DARK REV reaches it, and not TRANSIENT's there.

The pump loads an effect into the first of its homes whose block holds no other demand effect and whose track's FX2 is not a
reverb that reaches the code. When such a reverb arrives on the block of a loaded effect that a track uses, and another home is
free, the pump withdraws the effect and loads it into that home (a short dry gap, no toast). A reverb on the FX2 of an
unused loaded effect's block takes the block at once.

| situation | what happens |
|---|---|
| the chooser picks effect X, and a home is free | goes through |
| the chooser picks X, no home is free | refused, toast `EVICT Tn FX2 1ST` (Tn: its first home's track). An FX2 choice on the track of one of its homes goes through: it replaces the reverb |
| the chooser picks a reverb on a loaded, used X's block, and X has another free home | goes through; X moves |
| the same, and X has nowhere to move | refused, toast `EVICT <effect> 1ST` |
| any other route (song load, pattern, Part, paste): X used, no home free | X is not loaded and stays dry; toast `EVICT Tn FX2 1ST` at the next page key |
| any other route: a reverb reaches a loaded X that cannot move | X stays loaded, the reverb runs dry; toast `EVICT <effect> 1ST` at the next page key |

Both toasts are shown once per collision. When the holder goes away the other takes the block: the pump loads X, and a dry reverb
resumes (it runs the stock init first if its init never ran).

- **DLPUMP** (ColdFire, `modules/dlpump`), called from LOAD METER's entry code (`lm_in`, weak symbol) every frame interrupt.
  Idle: on ping-0 frames it compares the ids on the 16 live FX slots with the effects loaded and arms one message: a load when
  an effect has been used, not loaded, and its block not under a reverb for 200 idle calls in a row (about 145 ms: a project load writes the ids over a stretch of frames, and a reverb that arrives within it keeps the block; `DEBOUNCE` in `pump.s`, port-gated by `verify_dlload` `race`, not measured on a unit); a withdrawal when it is loaded and no slot uses it for 10 s in a row (a project load leaves every id at its default for about 4 s, measured on a unit; the `GRACE` build setting, 2 S for the port gates), or at once when a stock reverb is on the FX2 slot of its block.
  Sending: 100 halfwords per ping-0 frame to core B's `X:0x2901..`, then the doorbell `0xa55a` to `X:0x2900` two frames later.
  A load is sent three times, 30 idle calls apart, if the effect is still loaded each time; the copier copies only a send whose
  entry is not already bound at that address, so a load costs one copy when its first send arrives whole. The table of effects, their blocks and the toast
  strings is generated per remix (`remix.inc`, `Linked.include`) from `out/dsp/demand_records.json`; the unit reserves 2,600 code
  words an effect on every link. The FX1 and FX2 choosers' "same effect" test is detoured (the refusals above, with the popup
  `FUN_4005a2b8`, which runs in the key handler). The idle loop cannot call the popup, so it leaves its message in `dl_pend`,
  and a detour at the UI task's page-key handler (`FUN_4005578c`) shows it at the next press.
- **DLCOPY** (DSP, `modules/dlcopy/dlcopy.asm`), a hook on payload B at `P:0x76` (the frame head, after the masks are set), in
  the window. When the doorbell is set it clears the effect's BOUND word, copies the block to the window while summing the code
  words, compares the sum with the one staged after the code, and only then writes the effect's init and proc and BOUND last. A
  block whose sum is wrong is not published; the second send replaces it. A message for an entry that is BOUND with the same first
  word (a repeat send) is consumed without a copy: BOUND stays set, and a repeat that arrives damaged cannot unbind resident code
  (since 8 Nov 2026; `verify_dlstub`, not on a unit). A message with N = 0 only clears BOUND and the span.
- **The stub** (`modules/dlcopy/dlstub.asm`), assembled once by the build with a trampoline per effect. The effect's id
  dispatches to it. BOUND clear: the audio passes through (the stock null stub's loop). BOUND set: each instance runs the real
  init once, with `r0 n0 r6 r7 n7 m0 m1` kept, then jumps to the real proc.
- **The reverb guard** (`modules/dlcopy/dlwrap.asm`), one body in the window with a trampoline pair per reverb and payload (the
  stock entries differ). At init it reads the buffer base through `x:$213` and runs the stock init and proc only while
  `[base, base + extent)` misses the span of every loaded effect; otherwise the instance passes the audio through. The check is
  repeated every frame. A dry instance runs again as soon as the range is clear: after an init that never ran it runs the stock
  init from the proc (with `x:$213` pointed at the cell that holds its base), then the stock proc.

Layout (words are `X:` or `P:` as in the window, which aliases):

| where | what |
|---|---|
| `x:$33da3 + 8 k` (k = 0..4 in octabam, in the clear gap; DLCOPY follows the last) | effect k's entry: +0 BOUND (`$b0a5ed`), +1 real init, +2 real proc, +3 first window word, +4 the word after |
| `x:$2900` | staging: doorbell, k, destination offset, N, init offset, proc offset, then 2 N halfwords (code word as high 16 bits, then low 8), then the sum of the code words modulo 2^24 in the same form. Addresses are offsets into the window |
| `x:$3f00..$3f4c` | the stub's per-instance flags and saved registers; `x:$3dc0..$3e3f` the guard's state words and base cells, `x:$3fd0..$3fea` the trampolines' words, the guard's scratch and the copier's saved `b` |
| `P:0x33dcb..0x33e55` | DLCOPY (138 words; in `test/dlspike`, with four entries, `0x33dc3..0x33e4d`); the stub follows at `window_loader` (`0x33e66`; `0x33e56` in `test/dlspike`), then the guard's trampolines for payload A and B with their two shared loaders, the reverbs' records (stock init, stock proc, extent; three words a reverb and payload), then its body, then the hook stubs (to `0x33ff3` in octabam, build report of 8 Nov 2026: 17 words free between DLCOPY and the stub, 13 at the top) |
| `P:0x37da3..0x37eff` | LOAD METER's DSP half (A and B) |
| top of each slot | the effects, not uploaded: SPECTRUM `0x33820` (slot of T7), CHARACTER `0x37820` (T8), MODULATION `0x3b820` (T3), TRANSIENT `0x3fe00` (T4). The loader and LOAD METER sit above `0x33da3` and `0x37da3` in the first two slots, so those hold at most 1,411 words from `0x3820` (SPECTRUM, the larger of the two placed there, is 1,399); the third and fourth hold 2,016 |

The clear gaps are `0x33da3..0x33fff` (605 words) and `0x37da3..0x37eff` (349 words); resident code above `0x37f00` is wiped at
boot. octabam: see "Resident words" under SIDECHAIN_COMPRESSOR for the 28 Oct 2026 figures.

Builder: `Remix.window_demand` (keys), `Remix.window_guard` (stock keys), `Remix.window_loader` (address). The demand effects'
records are left out of payload A's upload and written to `out/dsp/demand_records.json`; the guards' addresses to
`out/dsp/guard_records.json`. The boot zero loop count ignores demand addresses.

## SIDECHAIN_COMPRESSOR: a hooked, soft demand effect (28 Oct 2026; port and `dsp_host` only)

Source: Zac-Kyoti/octatrack-kyoti-fw#4 (opt-in `FORM = SHARED`: one core-independent copy). octabam carries it in COMPRESSOR's row as a
demand effect with one home at `P:0x3f820` (1,711 words: 620 code, 65 table, 1,026 key window and counters as zeros), PLACE = DRAM.
Issue octabam#934; guard compaction octabam#947.

It has no dispatch entry of its own: `MenuEntry.stock_dsp` makes the row COMPRESSOR's, COMPRESSOR's stock init and proc stay, and four
`DspHook`s reach SC's code. So the block is loaded like any demand effect, and something resident has to sit in front of each hook.

**Hook stubs.** A demand effect with `DspHook`s and no init/proc has no id stub. Each hook's `jsr` goes to a resident stub the build
generates after the guard body: `move x:>BOUND,a`, `cmp #>$b0a5ed,a`, `beq` the body, else the displaced stock instruction
(disassembled from the site's words, refused unless it reassembles to them) and `rts`. The stock words are one tuple per hook in the
manifest, so one set of stubs serves both payloads where their sites hold the same words; the build writes each payload's `jsr`.
A bridged site is per payload. A hooked effect has one home, so the stubs jump to fixed addresses. Its block may overlap another demand
effect's (they never hold it at once); a memory dump for `dsp_host` leaves the later of two overlapping records out. In octabam: five
stubs, 47 words, at `0x33fbe..0x33fed`, 18 resident words left.

| hook | stock words (both payloads) | runs | stub when SC is not loaded |
|---|---|---|---|
| `sctap` (`A 0x4a7`, `B 0x29c`) | `66f000 000208` `move x:>$208,r6` | dispatcher, every track, every block | replay, `rts` |
| `moncommit` (`A 0x50e`, `B 0x303`) | `60f000 000206` `move x:>$206,r0` | dispatcher per-track commit | replay, `rts` (bridge below) |
| `scdet` (`A 0x1ab1`, `B 0x1871`) | `221e00 346100` | COMPRESSOR proc+0 | replay both, `rts` |
| `scinit` (`A 0x1aa4`, `B 0x1864`) | `44f400 0020c5` | COMPRESSOR init | replay, `rts` |

A stub may clobber `a` and the CCR at all four sites (✅ disassembly of both payloads): `sctap` reloads `a` at +3 and sets the CCR (`asr`)
before any conditional; `scdet` runs `mpy x0,x0,a` after the two replayed words; `moncommit` is LOAD METER's `otop_e2`, which already clobbers
`a`, `b` and the CCR there; `scinit`'s stock init only moves, and its caller (the dispatcher's init call, `A 0x4cd`/`0x503`, `B 0x2c2`/`0x2f8`)
reloads `a` and sets the CCR after the proc call. `tst` changes the condition codes the stock code sees after `rts` (JSR/RTS do not restore SR).
`dsp_asm` has no `jset`/`jcc` with these operands and writes a long `Bcc`'s absolute target as the displacement (the brclr trap in `AGENTS.md`),
so the build writes each stub's displacement as a number.

**The LOAD METER clash.** `moncommit` and LOAD METER's `otop_e2` hook the same instruction with the same stock words
(`modules/load-meter/manifest.py`, `COSTS.md`). `schema.Override` composes ColdFire `Detour`s only, so the ledger refused the pair.
`schema.DspOverride(site={"A": 0x50e, "B": 0x303}, module="LOAD METER")` is the DSP form: the ledger accepts the shared site and the
build does not plant LOAD METER's `jsr` there. SC's stub at that site calls `moncommit`'s body when loaded and then jumps to `otop_e2`, which stamps
the slot's cost and replays the displaced instruction; MON's crossfade lands before the end stamp, so the meter counts it. It is declared in
the bridge module [SC LOAD METER BRIDGE](../../modules/sc-loadmeter-bridge/README.md) (`requires` SIDECHAIN_COMPRESSOR and LOAD METER), which
octabam selects. It is not on SC's manifest because an `Override` is refused when the overridden module is not in the remix, and
`remixes/test/sidechain-compressor` and `test/kyoti-mute-sidechain` carry no LOAD METER. Precedent: SCOPE shares three ColdFire sites
with TUNER through `requires` and `overrides` (`modules/scope/manifest.py`).

**Soft.** A soft effect (`MenuEntry.stock_dsp`: the track runs the stock effect while the code is absent) is never refused by the
choosers, never refuses a reverb, and gives its block up at once to a reverb that reaches it (`modules/dlpump/README.md`).
The pump's trigger is the replaced effect's stock id (COMPRESSOR `0x18`), which is what the Part saves; `dl_tab` takes it from
`stock_dsp` instead of `menu.fx2_id`. Toasts: `SC KEY OFF: T4 FX2` (no home free), `SC KEY OFF: T4 REV` (a reverb took the block).
While the code is not loaded, page 2's KEY reads `--` (`dl_keyfmt`; issue #934).

**One core-independent copy.** The per-core source needs 677 words a copy (612 code, 16 `ptable`, 49 `ptable2`), two copies of the
per-core tokens (`@COREBASE@`, `@FCOREBASE@`, `@SBASE@`, `@FSBASE@`, `@GCNT@`, `@GSEED@`, `@FOREIGN_BR@`) = 1,354, and a 1,028-word
cross-core key window (4 tracks x 4 generations x 32 words, plus GSEED/GCNT, on each core's half). In the shared form every per-core token is computed from `x:$420`
(the track): `@COREBASE@` is `track & 4`; `slot(t, gen) = WBASE[t & 4] + (t & 3)*$80 + gen*$20`; `@FOREIGN_BR@` is `(my track xor KEY track) & 4`;
`@GCNT@`/`@GSEED@` move to core-private Y. One copy is 677 + `$400` = 1,701 words. The shared form is selected by a token
(`@SHARED@`, set only by octabam's demand layout); unset, the source assembles byte-identical to today (`seal()`), which keeps Zac's
standalone, KYOTI and Modwerk images pinned to their sha256.

**Where.** The free space above offset `0x3820` is 1,411 words in blocks 0 and 1 (the loader and LOAD METER sit above) and 2,016 in blocks 2
and 3; 1,701 fits blocks 2 and 3 only (`0x3b820` or `0x3f820`), the same ones MODULATION (1,561) needs. TRANSIENT's home at offset
`0x3e00` of that block is shared with SC's span, so the pump treats them as one block holder. SC is ahead of TRANSIENT in `window_demand`:
when both are wanted together (a project load) SC takes the block and TRANSIENT goes to another; if TRANSIENT already holds it when a
COMPRESSOR is picked, SC waits (`SC KEY OFF: T4 FX2`) until the block is free.

**Loader changes it needed.** The entry table at `x:$33da3 + 8 k` held exactly 4 entries (the build exits above 4); the fifth moved DLCOPY
to `0x33dcb` and the loader to `0x33e5e`. The window path takes a `ptable2` (placed behind `ptable`, as the harvested path does). The window
path plants hooks into window code. A `window_demand` module with hooks gets the stubs above and the pump gets its bodies' addresses.

**Resident words.** Before the change the build report (`make bus REMIX=octabam`, `origin/main` `b36afa2`, 28 Oct 2026) showed 21 free
words in runs of 6, 6 and 9, and the stubs needed 39. The guard's trampolines were then 156 words of immediates (11 + 15 a reverb and
payload, three `move`s of constants to `x:$3fd1..$3fd3` and a `jmp (r2)`); table-driven they are 70 words plus 18 of records (the
stock init, stock proc and extent, three words a reverb and payload), the body unchanged at 152. The guard ends at `0x33fb6`, leaving 74 free at `0x33fb6..0x33fff`, plus
the 6 and 9 beside LOAD METER's two halves (`0x37e4a..0x37e4f`, `0x37ef7..0x37eff`).

**Compatibility.** Nothing changes for remixes without the loader: stubs are generated only for a `window_demand` module, the bridge is a module they do not
select, and the build changes are proved by `scripts/refhash.sh check`. Saved projects and Parts are untouched (COMPRESSOR's slots, ids and
defaults stay; unloaded, it runs as stock COMPRESSOR). `octabam` and `test/dlspike` images changed (DLCOPY and what follows moved up 8 words).

**Gates** (local, 28 Oct 2026): `verify_dlhook` 40 PASS (a broken stub, `beq` -> `bne`, fails 12), `verify_dlstub` 48, `verify_dlwrap` 224
(199 on `octabam`, 125 on `test/dlspike` after the compaction; a mutated loader with extent and stock proc swapped hangs `dsp_host` on the first
wrapper run); `verify_dlload` under the port: the PR.

**Rejected.** Load-time hook patching (the copier writes the `jsr` into stock P when SC loads and restores it on withdraw): core B cannot write
core A's P, core A would need its own patcher hook, and the instruction cache would have to be shown not to hold the old words. SC on
COMPRESSOR's dispatch: the stub's unbound path is a dry pass-through where it would have to run stock COMPRESSOR, and the dispatcher hooks would
still need resident stubs. Moving `otop_e2` to another dispatcher site: changes LOAD METER's figures, which `COSTS.md` is built on.

## Measured on a unit (26 Oct 2026, MKII, images DLPROBEJ1..J7, project MXDLPR01 / MXDLPR02)

- DLPUMP runs on the unit: the pump's counters (`tools/hw/dl_state.py`, USB request `0xc0/0x57` block 3) show the frame interrupt calling it 2,756 times a second, the ping word alternating 0 and 1 as in the port, and the loads, chunks and doorbells it armed and sent.
- The host write lands in core B's `X:0x2900..`: DLPROBE on T1 read `X:$2902` = `0x00d000` (TRANSIENT's destination offset).
- The byte above a host word's 16 bits is stale on the unit: the doorbell read `0x40a55a`. The port leaves it 0. The first image compared the doorbell as a full word and never took a block (received 0, doorbell non-zero for ~77,000 frames). The copier now masks the doorbell and header words (`verify_dlstub`, "stale high byte").
- With the mask: all four effects BOUND, every block's sum matched (refused 0), published equal to received.
- The code runs, from the per-slot costs of LOAD METER (`tools/hw/load_meter.py`; a dry slot costs 89..147 counts): CHARACTER on core A FX1 5,147; SPECTRUM on core B FX1 4,062; TRANSIENT on core A FX2 3,616; MODULATION on core B FX1 323 (module defaults). So code core B copied is executed by core A.
- SPECTRUM and CHARACTER on an FX2 slot cost a dry slot's 116..119 counts: they are `fx1_only` and render dry there. `octabam` had no FX1 list, so it offered them on FX2 only; it lists them on FX1 now.
- A project load leaves every id at its default for about 3.8 s (polled over USB every 0.25 s: ids reset at 36.2 s, back at 40.05 s). With a 2 s grace the pump withdrew all four effects at 38.3 s and loaded them again at 40.05 s; the grace is 10 s.

## Open

- OPEN, hardware: a move from T4's block freezes the DSP frame loop (`FAILURE_MODES.md`, "DARK REV picked on T4's FX2 ..."). `octabam` still has `window_homes`. A poll caught DSP 1 at 99.8 % in a single frame at the copy of a send (15.544 s, 28 Oct 2026): copying a block in one frame takes core B close to a frame.
  Since 8 Nov 2026 the loop is 9 instructions and 10 words a code word instead of 11 and 13, and the two repeats of a send that
  arrived whole are not copied. Estimated from the code (2 cycles a one-word instruction, as `CHIP.md` measures; 4 assumed for a
  two-word one; wait states for fetches and P writes in the window not counted): MODULATION's 1,561 words went from about 41,000
  cycles to about 31,000, against a frame of 72,512. 🟡 not measured on a unit. Copying a slice per frame (a cursor in the entry,
  BOUND after the last slice) is the change that would bound it; not made.
- The unit: the audible dropout while an effect loads (about 25 ms), and a reverb meeting a loaded effect's block.
- Core A's stall when sent to, and the mask at the frames that lose their chunk.
- How long the deferred toasts wait for a page key; whether 2 s (120 ticks) is long enough to read.
- A dry instance that had run its init (state 3) resuming is not covered by a gate: `dsp_host` cannot change the published span between blocks.
- The check is blind to a block lost in transit on the unit beyond what the sum catches: the sum is 24 bits.
- Audio at a load: the stub is dry until the code arrives, about 70 frames (25 ms) for MODULATION.

  "warm" count reset when it first runs after a load. 🟡
